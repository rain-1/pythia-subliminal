You are Codex. Implement an experimental framework for testing subliminal learning in PolyPythia base models using activation-steered teachers and filtered mixed-format numeric carrier data.

Goal
====

Build a reproducible Python codebase that can run the following experiment:

1. Take a base causal LM from the PolyPythia/Pythia family, preferably starting with 410M and a small number of random seeds.
2. Build a trait steering vector from contrastive text snippets, e.g. GOTHIC vs NEUTRAL or LEGAL vs NEUTRAL.
3. Use the steered base model as a teacher to generate mixed-format numeric-only carrier data.
4. Strictly filter the generated data so the visible data contains no trait words and no alphabetic text.
5. Fine-tune a fresh copy of the same base model on this numeric-only carrier data.
6. Evaluate whether the trait transferred using only non-LLM metrics:
   - target-token logprob mass shift,
   - generated target-token frequency,
   - activation alignment with the original steering vector.
7. Add controls:
   - neutral/unsteered numeric carrier data,
   - random-vector-steered carrier data,
   - shuffled/unigram-matched numeric data,
   - divergence-only and divergence-masked data if feasible.
8. Support cross-seed transfer matrices:
   - data generated from seed s,
   - student initialized from seed r,
   - evaluate whether transfer is same-seed-specific or stable across seeds.

This codebase is for mechanistic research. It should be modular, inspectable, and easy to run in small stages. Do not build a monolithic script.

Core scientific claim to test
=============================

We want data where the trait is not obvious in the training data, but training on the data imbues the model with the trait, demonstrable with algorithmic evaluations.

Concrete first claim:

A PolyPythia/Pythia base model trained only on filtered, mixed-format numeric sequences generated by a GOTHIC-steered teacher later assigns higher probability to held-out gothic tokens and/or shows activation shifts aligned with the gothic steering vector, compared to neutral-number and random-vector controls.

Important constraints
=====================

- These are base models, not instruction-tuned models.
- Do not evaluate with question answering, chat prompts, or long ICL prompts.
- Treat the model as a document continuation model.
- Use short neutral prefixes and direct logprob/activation metrics.
- Avoid LLM judges entirely.
- The generated training data must contain no alphabetic characters if using numeric carrier data.
- Store enough metadata to analyze data format, steering strength, seed, model, trait, and generation settings.

Trait vector computation
========================

Implement steering.py.

Function:
compute_trait_vector(model, tokenizer, positive_texts, negative_texts, layers, token_positions)

Use residual stream hidden states from model outputs with output_hidden_states=True.

For each text:
- tokenize;
- run model;
- extract hidden states at requested layers;
- average over selected token positions.

Token position options:
- "last": last non-padding token
- "all": all non-padding tokens
- "content": all tokens except first; simple default is "all"

Trait vector:
v[layer] = mean_positive_hidden[layer] - mean_negative_hidden[layer]

Save:
outputs/trait_vectors/{model_id_safe}/{trait}/{seed}/layer_{l}.pt
with metadata JSON:
- model id
- trait
- layer
- positive snippets
- negative snippets
- pooling method
- vector norm
- dtype

Also implement normalize vector option.

Carrier generation design
=========================

Use mixed-format numeric sequences by default.

Do NOT use only one format. The user's prior experiments found that only one numeric format failed; varied numeric sequence formats worked better.

For each sample:
- choose a format template from a balanced set,
- choose number width from {2, 3, 4},
- choose length from {16, 32, 64, 128},
- generate numeric items using the steered model constrained to numeric tokens if feasible,
- render the numeric items through the chosen format.

Important: keep format distribution exactly balanced across:
- steered trait data,
- neutral data,
- random-vector data.

Templates:

space:
  "381 047 922 105"

comma:
  "381, 047, 922, 105"

semicolon:
  "381; 047; 922; 105"

pipe:
  "381 | 047 | 922 | 105"

newline:
  "381\n047\n922\n105"

bracket_comma:
  "[381, 047, 922, 105]"

slash:
  "381 / 047 / 922 / 105"

hyphen:
  "381-047-922-105"

Optional later:
- multi-row tables with only digits and punctuation.

Simplifying implementation:
First version can generate numbers token-by-token under constrained decoding, then normalize/render them into formats. This slightly weakens the "teacher chose separators" channel, but makes format balancing clean.
Second version can let teacher generate the entire string with constrained allowed chars/tokens.

For each model checkpoint:

- compute logsumexp over held-out trait target token IDs.
- compute logsumexp over control token IDs.

- neutral-number-trained model,
- random-vector-number-trained model,

Output CSV/JSON:

If target/control strings are multi-token, implement optional sequence logprob:

Evaluation: generated token frequency

Evaluation: activation alignment
================================

Implement eval_activation.py.

For base model M and trained model M':
- run both on the same held-out neutral prefixes.
- collect hidden states at trait vector layer(s).
- compute delta_h = mean(h_M_prime - h_M) over selected positions.
- compute:
  cosine(delta_h, v_trait)
  dot(delta_h, v_trait)
  norm(delta_h)
  projection_fraction = dot(delta_h, v_trait) / (norm(v_trait)^2)

Also compare to:
- neutral-trained model,
- random-vector-trained model.

Output CSV/JSON.
