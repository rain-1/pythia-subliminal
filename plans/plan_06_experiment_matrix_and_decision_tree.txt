PLAN 06: EXPERIMENT MATRIX AND DECISION TREE
How to choose the first 4-5 executions

Recommended first 5 experiments
===============================

Experiment 1: LLS-SFT animal preference
---------------------------------------

Trait: owl or panda vector.
Carrier: mixed numeric/log/table candidates generated by neutral base model.
Teacher role: steered model scores candidates.
Training: SFT on top-ratio hard continuations.
Eval: target-token logprob, activation projection, heldout carrier margin.

Why first:
- Cleanest base-model setup.
- Low leakage.
- Directly tests latent selection -> hard-token SFT.

Experiment 2: DPO animal preference
-----------------------------------

Trait: same vector as Exp 1.
Carrier: same candidate pool.
Teacher role: steered model chooses preferred continuation.
Training: DPO on top-vs-bottom pairs.
Eval: preference agreement, target-token logprob, activation projection.

Why second:
- Tests whether hard preference labels alone transmit the trait.
- Reuses Exp 1 infrastructure.

Experiment 3: Direct steered generation with mixed numeric formats
------------------------------------------------------------------

Trait: same vector.
Carrier: multi-format numbers/tables/logs.
Teacher role: steered model generates hard text.
Training: SFT.
Eval: same as Exp 1, plus leakage rate by alpha.

Why third:
- Closest to original subliminal learning.
- Tests whether direct steered generation is stronger than selection.

Experiment 4: Style/persona trait via LLS-SFT
---------------------------------------------

Trait: terse vs ornate, cautious vs risky, or technical vs poetic.
Carrier: neutral prose/procedural text.
Teacher role: steered model scores candidates.
Training: SFT on top-ratio hard continuations.
Eval: style classifier/logprob pairs, activation projection, free generation.

Why fourth:
- Moves beyond target-token animal preference.
- Tests more distributed traits.

Experiment 5: Tool/action prior via DPO or SFT selection
--------------------------------------------------------

Trait: backup-first vs modify-first, chmod-first vs chown-first, inspect-before-delete vs delete-first.
Carrier: shell/API transcript documents.
Teacher role: steered scorer or preference selector.
Training: DPO or selected-SFT.
Eval: logprob of next action token, trajectory generation.

Why fifth:
- Tests procedural/policy transfer rather than semantic preference.
- Closer to agent safety.

Decision tree
=============

If Exp 1 works:

- Run anti-vector selection.
- Run data-size scaling.
- Run alpha scaling.
- Run carrier ablations.
- Move to DPO and direct generation.

If Exp 1 fails:

Check in order:

1. Does v_T actually steer the base model on behavioral evals?
   If no: rebuild vector or choose easier trait.

2. Does v_T change likelihood ratios on carrier candidates?
   If no: carrier is insensitive; switch carrier or increase alpha.

3. Is selected data too similar to random data?
   If yes: increase K candidates, alpha, or select more extreme quantiles.

4. Is training too weak?
   If yes: increase data, LR, train steps, or use full fine-tune rather than LoRA.

5. Is eval too chat-like?
   If yes: replace with document-completion logprob evals.

If DPO works but SFT selection fails:

- Preference boundary is stronger than selected distribution.
- Explore DPO beta, candidate count, and pair matching.

If SFT selection works but DPO fails:

- DPO implementation/objective may be unstable.
- Try pairwise SFT: train chosen continuations only and compare to rejected-only.

If direct generation works but selection fails:

- The steered teacher generates signals not captured by likelihood-ratio selection.
- Run divergence-token analysis.

If selection works but direct generation leaks too much:

- Use selection as primary method.
- Direct generation may be unsuitable for that trait/carrier.

If animal preference works but style/persona fails:

- Trait vector may be too weak or eval too noisy.
- Build better contrast sets and use pairwise logprob evals.

If style/persona works but animal fails:

- Animal preference may be too token-specific or filtered away.
- Try fictional entities or broader sentiment traits.

Minimal implementation order
============================

Week 1:
- Build trait-vector code.
- Build document-completion eval harness.
- Validate steering on base model.

Week 2:
- Build candidate generation and likelihood-ratio scoring.
- Build filtering and selection.
- Train first SFT students.

Week 3:
- Add checkpointed eval charts.
- Run alpha/data-size sweeps.
- Add random/bottom/anti controls.

Week 4:
- Add DPO pipeline.
- Compare SFT selection vs DPO.

Week 5:
- Run direct steered generation and divergence-token analysis.

Week 6:
- Move to second trait class: style/persona or tool/action.

Core go/no-go criteria
======================

Continue a line if:

- explicit leakage is low/moderate;
- selected/steered student beats neutral/random controls;
- effect appears in at least two eval layers;
- effect scales with alpha or data size;
- anti-vector or bottom-selection gives opposite or weaker effect.

Drop or redesign a line if:

- filtering removes most data;
- selected data is obviously semantically trait-related;
- only free-generation keyword counts move but logprob/activation metrics do not;
- controls move equally;
- effect disappears under minor eval-template changes.
